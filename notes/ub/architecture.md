# UtilityBelt (UB) architecture notes

Source: C:\Scripting\AC_Unreal_ref\UtilityBelt (read-only). Paths below are relative to it. Written from grep/selective reads; "unclear" = not verified.

IMPORTANT: several core pieces are NOT in this repo (referenced DLLs in `deps/`): `UtilityBelt.Helper.dll` (namespace `UBHelper`, native/AcClient memory hooks), `UtilityBelt.Service` (UBService: Settings classes, UBNet, SettingsEditor, CellDat/PortalDat readers, `UtilityBelt.Common.Enums`), `AcClient` (unsafe client struct bindings), `MoonSharp.Interpreter.dll` (Lua interpreter, present in deps but only referenced from a commented-out file). UBLoader's `FilterCore.Scripts`/`UBScript` (UB Lua scripting) is referenced only in commented-out code (UtilityBelt/Lib/ScriptInterface/RemoteScript.cs) - no live Lua system in this repo.

## 1. Startup / loader
- UBLoader (UBLoader/FilterCore.cs) is a Decal *Filter* (`FilterBase`), loaded by Decal at client start. UtilityBelt.dll is the actual plugin, loaded by the filter via `Assembly.Load(bytes, pdbBytes)` (FilterCore.cs:438-470) so the DLL can be hot-reloaded (`HotReload` global setting + FileSystemWatcher on UtilityBelt.dll).
- Loader embeds LiteDB, Antlr4.Runtime, websocket-sharp as resources and `Assembly.Load`s them (FilterCore.cs:152-156).
- Loader reacts to `UBHelper.Core.GameStateChanged`: at character-select it shows loader UI (settings editor, optional character creation UI, auto-login via `LoaderLogin`: `AcClient.CPlayerSystem.GetPlayerSystem()->LogOnCharacter(id)`), unloads/loads plugin assembly on login/logout (FilterCore.cs:300-335).
- Loader parses raw server messages via `EchoFilter.ServerDispatch` to learn account/server name: 0xF658 (zonename -> account), 0xF7E1 (server name), 0x02DD and 0xF7B0/0x0013 (PlayerDesc skill training state). Used for per-account settings file (FilterCore.cs:372-423).
- Loader also has ClientHealthMonitor (kill disconnected / logged-out / unresponsive clients), global FrameRate limiter, exception logging.
- `UtilityBeltPlugin.Startup(assemblyLocation, storagePath, databaseFile, host, core)` (UtilityBelt/UtilityBelt.cs:222): grabs world name via `AcClient.Client.m_instance->m_worldName`, character name via `UBHelper.Core.CharacterSet[LoginCharacterID]`, gets the raw IDirect3DDevice9 from `Decal.Underlying.GetD3DDevice` (used for custom 3D drawing), hooks `Core.CommandLineText`. Then waits for `CharacterFilter.Login` (or runs Init immediately if already logged in) -> `Init()`.
- Init order (UtilityBelt.cs:279): Util dirs -> Logger -> UBHudManager -> LiteDB Database -> views (MainView, ItemGiverView, DungeonMapsView, LandscapeMapsView; VirindiViewService XML UI) -> HotkeyWrapperManager -> LoadTools -> InitSettings -> InitCommands -> InitHotkeys -> InitExpressions -> tool.Init() for each -> views Init -> optional UpdateChecker.
- Shutdown: save dirty settings, unhook, dispose tools/views/huds, flush files.

## 2. Tool registration
- `UtilityBeltPlugin` has one public instance field per tool (UtilityBelt.cs:154-199, 40 tools). `LoadTools()` reflects over public fields whose type derives `ToolBase`, requires exactly one `[Name("X")]` attribute, `Activator.CreateInstance(type, ub, name)`. No manual registry.
- `ToolBase` (Lib/ToolBase.cs): `Init()`, `Dispose()`, `RenderUI()`, helpers LogDebug/LogError/WriteToChat/ChatThink (Util.Think = chat "think" to self). Tools are also `ISetting` nodes (settings tree: `Tool.Setting`).
- Attributes (Lib/Attributes.cs): Name, Summary, FullDescription (markdown docs), Usage, Example, CommandPattern(verb, regex, allowPartialVerbMatch), Hotkey(title, desc), ExpressionMethod(name), ExpressionParameter(idx,type,name,desc,default), ExpressionReturn, Section, Default* (color/enabled/size...), DefaultChatColor.
- Tool event model: tools mostly subscribe to Decal events in Init()/when `Enabled` changes, and unsubscribe in Dispose. Many use `Core.RenderFrame` as a per-frame state-machine tick (Assessor, Jumper, Looter, AutoVendor, ...). Standard pattern: setting `Enabled` with `.Changed` handler that calls Enable()/Disable().
- `ActionQueue` (Lib/ActionQueue.cs): static helper that runs per-RenderFrame job callbacks over lists of object ids with heartbeat timeout; used for multi-item operations.

## 3. Settings system
- Declared as fields on the tool: `[Summary("..")] public readonly Setting<T> Name = new Setting<T>(default[, changedCallback])`. Other kinds: `CharacterState<T>` (per-character persisted state, in state.json), `Global<T>` (loader-level), `Setting<ObservableCollection<..>>/ObservableDictionary` for lists, `[DontShowInSettings]`, `[Hotkey]` on bool settings creates a toggle hotkey.
- Implementation class `UtilityBelt.Service.Lib.Settings.Settings` is in the external UBService DLL (not here). Observed API: ctor `(owner, filePath, predicate(setting)->bool, defaultsPath, name)`, `.Load()`, `.Save()`, `.NeedsSave`, `.Changed` event (SettingChangedEventArgs.Setting), ISetting.GetValue/SetValue, `FullDisplayValue()`. JSON files, dirty-flag saved (on shutdown + other triggers, unclear).
- Six Settings instances (UtilityBelt.cs:325-348), filtered by `SettingType`:
  - `Settings` (Profile): `<pluginDir>/<World>/<Character>/settings.json` when profile == "[character]", else `<pluginDir>/profiles/<name>.settings.json`; defaults from `settings.default.json` next to DLL.
  - `State`: `<character dir>/state.json` (CharacterState<T>: window positions, targets, tags...)
  - `ClientUISettings`: Client.ClientUIProfilePath (UI element layout)
  - `PlayerOptionsSettings`: PlayerOptions.CharacterOptionsProfilePath (in-game options)
  - `AliasSettings`: `aliases.json` (character or profile)
  - `GameEventsSettings`: game events profile
  - Loader: `SettingsGlobal` = `<UBLoader dir>/utilitybelt.settings.json`; `SettingsAccount` = `<PluginStorageDirectory>/<server>/<account>.settings.json`.
- Directories: plugin storage default `Documents\Decal Plugins\UtilityBelt` (Global.PluginStorageDirectory); character dir = `<storage>/<WorldName>/<CharacterName>` (Lib/Util.cs:72-100); profiles dir `<storage>/profiles`; LiteDB `utilitybelt.db` in storage; logs in LogDirectory (`exceptions.txt`, per-day `*.YYYY-MM-DD.txt`, `chat.txt` per character).
- Settings UI: auto-generated from attributes (Views/SettingsView, UBService SettingsEditor). `/ub opt list|get|set|toggle` is the CLI (Plugin.cs:217).
- Loader global settings: PluginStorageDirectory, DatabaseFile, LogDirectory, HotReload(false), FrameRate(0), UploadExceptions(true), ShowCharacterCreationUI, KillDisconnectedClients, KillLoggedOutClients (+timeout 60s), KillUnresponsiveClients (+timeout 120s).

## 4. Command dispatch (`/ub ...`)
- `Core.CommandLineText` handler (UtilityBelt.cs:445): regex `^[/@]+ub( |$)`; sets `e.Eat=true`; verb = second token. Exact verb lookup in `RegisteredCommands` (built by reflecting `[CommandPattern]` on all public tool methods, duplicate verbs rejected). Fallback: `AllowPartialVerbMatch` commands match when `verb.StartsWith(key)` (this is how `/ub givep`, `vendor openp`, `fellow recruitp` suffix variants work); else Damerau-Levenshtein <=2 "did you mean".
- Args = remaining text; matched against the command's regex (IgnoreCase, named groups); mismatch -> "Bad command syntax" + help. Handler signature `void Name(string verb, Match args)`.
- `/ub help [cmd]`, `/ub opt`, `/ub mexec <expr>` live in Plugin.cs. Aliases tool (Tools/Aliases.cs) is a second `CommandLineText` listener: user regex -> Expression / ChatExpression / ChatCommand actions (Lib/Actions/*), captures set expression vars `capturegroup_<name>`. Aliases cannot override plugin commands.

## 5. Expression engine
- Meta expressions = VTank's expression syntax, re-implemented by UB. Grammar: Lib/Expressions/MetaExpressions.g4 (ANTLR4; runtime Antlr4.Runtime.dll loaded from resource). Evaluator: `ExpressionVisitor` (Lib/Expressions/ExpressionVisitor.cs, 610 lines).
- Syntax: function call `name[arg, arg]`; vars `$name` (local), `@name` (persistent, per char), `&name` (global, per server); assign `$x = expr`; index/slice `x{i}`, `x{a:b}`; regex match `a # b`; operators `+ - * / % ^(power) & | ^(bitwise) ~ << >> == != < > <= >= && ||`; literals: numbers, hex `0x..`, bool, strings (bare words / backtick quoted); `;` sequences statements. Truthiness: `IsTruthy` (ExpressionVisitor.cs:256).
- Value types: double/int/string/bool plus ExpressionList, ExpressionDictionary, ExpressionWorldObject (wrapper over WorldObject), ExpressionCoordinates, ExpressionStopwatch, ExpressionUIControl (Lib/Expressions/*).
- Registration: any public tool method with `[ExpressionMethod("name")]` + `[ExpressionParameter]`/`[ExpressionReturn]` is reflected into `RegisteredExpressions` (UtilityBelt.cs:523). Invoked via `RunExpressionMethod`.
- HOW IT PLUGS INTO VTANK: `VTankControl.PatchExpressionEngine` (default FALSE) makes `VTankExtensions.PatchVTankExpressions()` use HarmonyLib runtime patches (prefixes) on obfuscated VTank internals (uTank2 classes: expression action, expression, chat capture, button expression, expression chat action, uboptget/uboptset; VTankExtensions.cs:277-340) so VTank metas evaluate through UB's engine. UB's own `/ub mexec`, aliases, game events and `exec` call `VTankControl.EvaluateExpression/CompileExpression` directly regardless.
- Variable storage: local vars in-memory dict; persistent vars `@x` = LiteDB collection `persistent_variables` keyed (Server, Character, Name) with an in-memory cache; global vars `&x` = `global_variables` keyed (Server, Name) (VTankControl.cs:140-430).
- Debug cmds: `/ub listvars|listpvars|listgvars`.

## 6. Scripting / Lua

## 7. UB Service & Networking (client-to-client)
- Tools/Networking.cs uses `UtilityBelt.Service.UBService.UBNet.UBNetClient` (external). Transport: a local TCP server hosted by UBService (per tool docs "local tcp server"); clients on the same PC connect. Messages are protobuf-net (`[ProtoContract]`) in Lib/Networking/Messages.
- API used: `UBNetClient.Id, IsConnected, Clients, Tags, AddTags/RemoveTags, SubscribeToChannel("utilitybelt"), PublishToChannel(channel,obj), SendBroadcastRequest(obj, ClientFilter, progressHandler, timeout), SendBroadcastResponse, events OnRemoteClientConnected/Updated/Disconnected, OnConnected/OnDisconnected, OnTypedChannelMessage, OnTypedBroadcastRequest`. ClientType.GameClient.
- Message types: ClientData (id, world, player id, health/mana/..., position), VitalUpdateMessage (cur/max H/S/M), CharacterPositionMessage (landcell, heading, NS, EW, Z), CastAttemptMessage (spell, target, skill), CastSuccessMessage (spell, target, duration), TrackedItemUpdateMessage/TrackedItemStatus (icon, name, count), CommandBroadcastRequest/Response (command, delay, target tags).
- Features on top: `/ub bc`, `/ub bct` (run chat command on other clients, tag filtered, per-client delay), tags (`Networking.Tags`), `netclients[tag]` expression, NetworkUI hud, VTankFellowHeals (feeds other clients' vitals/casts into VTank), VTankExtensions.BetterFollowing (real locations from UB net).

## 8. Hotkeys / UI / HUD
- Hotkeys: `[Hotkey(title, desc)]` on tool methods or bool settings -> `HotkeyWrapperManager.AddHotkey` (Lib/HotkeyWrapper.cs) wraps VirindiHotkeySystem (`VHotkeySystem.InstanceReal.AddHotkey`, plugin name "UtilityBelt", `Fired2` event). Default key unbound (vk 0); user binds in VHS UI.
- Windows UI: VirindiViewService XML views (Views/*.xml + .cs): MainView, SettingsView, ItemGiverView (ig), DungeonMapsView, LandscapeMapsView, NetworkClientsView, editors (ColorPicker, ListEditor, DictionaryEditor, EnumFlagEditor, ...). Controls: HudButton, HudCheckBox, HudList, HudCombo, HudTextBox, HudStaticText, HudPictureBox, HudFixedLayout. `GUI` tool (Tools/GUI.cs: MaxFramerate 60, EnableDemoUI, EnableGameStateInspector) wraps a newer UBService GUI (external).
- Custom HUD overlays: `UBHud`/`UBHudManager` (Lib/UBHud/*) use VVS/Decal D3D HUD textures (`DxTexture`, `Texture.WriteText`, shapes, mouse events, ctrl-drag to move, close box). Used by Arrow, DerethTime, Movement debug keys, XPMeter, NetworkUI, Player inspector, DungeonMaps, LandscapeMaps.
- True 3D drawing (OverlayMap ~40 uses of `D3Ddevice`) uses a `Microsoft.DirectX.Direct3D.Device` wrapping the client's IDirect3DDevice9, drawn from `Core.RenderFrame`. VisualNav / Nametags also render in-world (details in tools.md, partly unclear).
- Chat output: `Logger.WriteToChat(msg, type)` -> `Core.Actions.AddChatText` with per-type colors + optionally mirrored to VTank (`vTank.Tell`), file log.
